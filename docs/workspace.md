# Локальный Yggdrasil Workspace

Yggdrasil 0.18.0 включает локальный интерфейс с независимой версией
**UI 0.1 Experimental**. `ygg` без аргументов открывает проекты, знания,
источники, Operations и Settings. `ygg --help`, `ygg -help` и `ygg help` выводят
справку. Все существующие команды CLI сохранены.

Graph и Chat временно скрыты из навигации, страниц проектов и действий над
записями. Это ограничение экспериментального интерфейса: сохранённые диалоги,
связи и серверные модули остаются на месте. Интерфейс продолжает развиваться;
его версия не совпадает с версией пакета Yggdrasil.

Если `ygg` установлен через pipx из опубликованной версии, изменения checkout
не меняют эту установку. Чтобы использовать собранную версию из корня репозитория:

```sh
pipx install --force .
ygg redeploy
ygg ui --restart
```

`redeploy` обновляет код уже работающего движка, сохраняя базу памяти.
`ui --restart` перезапускает собственный веб-сервер после обновления;
сначала завершите или остановите команды, запущенные в Workspace.
Из исходников сам Workspace также запускается через
`python3 -m yggdrasil.ygg_workspace`; движок должен поддерживать новое API.

```sh
ygg
ygg ui --no-open
ygg ui --port 42071
```

Workspace слушает только `127.0.0.1`, по умолчанию порт `42070`.
Повторный запуск переиспользует работающий сервер. Если порт занят другим
процессом или Workspace другого пространства, выберите другой порт.
В окружении без браузера откройте выведенный адрес самостоятельно.
Разрешение входа в адресе одноразовое и действует 60 секунд; для новой
ссылки повторите `ygg`. Сессия браузера действует 12 часов.

## Проекты и данные

Проекты появляются из сохранённых записей памяти. «Без проекта» содержит
записи без `metadata.project`. Проекты, чаты и источники ограничены текущими
`user_id` и `namespace` из конфигурации Yggdrasil. «Все проекты» не объединяет
разные пространства имён.

В проекте доступны обзор, поиск и фильтры знаний, источники.
Счётчики отражают реальные записи; дата последней записи — время её добавления,
поскольку существующий движок не хранит отдельное время редактирования.

Раздел Operations запускает существующие команды CLI прямо из браузера.
Для начального наполнения выберите `seed`: по умолчанию заполнен `--dry-run`,
чтобы сначала посмотреть план импорта. Доступны импорт и настройка расписания.
Можно передать те же аргументы, что и в терминале.
Команды CLI по-прежнему работают независимо от веб-интерфейса.

## Скрытые Graph и Chat

В UI 0.1 Experimental граф и чат недоступны через страницы, навигацию и кнопки
«Обсудить в чате». Их временное скрытие не удаляет ранее сохранённые данные.
Диалоги остаются в `$YGG_HOME/workspace.sqlite` (по умолчанию
`~/.yggdrasil/workspace.sqlite`), настройки — в `workspace_chat.json`, ключ
провайдера — в `workspace_chat_key` с правами `0600`. Диалоги не превращаются
автоматически в память и пока не включаются в `ygg sync`.

Выбор моделей для фоновой обработки и embeddings доступен в Settings.
Каталог показывает установленные модели Ollama или OpenAI-совместимого
сервера, включая LM Studio. Недоступный сервер и пустой каталог показываются
отдельно; список можно обновить. Настройки скрытого чата сохранены отдельно
и не заменяют настройки фоновой обработки или embeddings.

## Язык интерфейса

По умолчанию используется английский. Переключатель языка сохраняет выбор
в браузере. Поддержаны все языки README: English, Русский, Deutsch, Español,
Français, 日本語 и 中文. Даты и числа следуют выбранному языку. Пользовательские
записи, ответы модели и исходный вывод CLI не переводятся автоматически.

## Версия, обновления и GitHub

Под логотипом показаны установленная версия и ссылка на GitHub с числом звёзд.
Метаданные PyPI и GitHub загружаются в фоне и кэшируются на час. Если GitHub
недоступен и сохранённого числа нет, вместо звёзд отображается «—».

При доступном обновлении рядом с версией появляется значок. Нажатие открывает
подтверждение; Update now запускает тот же `ygg update`, что и терминал.
Модалка показывает настоящий вывод команды. Её можно скрыть и открыть снова:
обновление продолжится, а рядом с версией останется индикатор выполнения.

Нулевого кода завершения недостаточно: Workspace проверяет установленную
версию. При успехе он перезапускается на новом коде, сохраняя текущую сессию
через одноразовый локальный файл с правами `0600` и сроком 60 секунд. Вывод
команды в этот файл не переносится. После перезапуска появляется уведомление
Sonner (shadcn/ui). Если другая операция не позволяет перезапуск, модалка
покажет ошибку и предложит повторить его. Ошибка установки остаётся в логе;
повторная попытка доступна и после частично выполненного обновления.

Если обновлений нет, нажатие на версию открывает GitHub Releases.
Выбор языка находится в меню с иконкой перевода: флаги и названия языков
отображаются локально, без загрузки картинок с внешних серверов.

## Оформление

Settings → Appearance предлагает пять палитр: нейтральную (белый/графитовый),
зелёную, синюю, оранжевую и розовую. У каждой есть светлый и тёмный варианты.
Образцы показывают выбранный режим. Палитра применяется ко всему интерфейсу,
включая боковую панель. Быстрый переключатель режима в верхней панели
сохраняет выбранную палитру.

Изменения применяются сразу и сохраняются в браузере, отдельно от настроек CLI.
Выбор синхронизируется между вкладками; существующее предпочтение тёмной темы
сохраняется. По умолчанию остаётся зелёная палитра.

## Настройки и операции

Settings → Configuration показывает все параметры реестра `ygg config`,
включая embeddings, фоновую модель, идентификатор пользователя и пространство.
Изменения сохраняются в тот же `$YGG_HOME/config.json`, секреты — в отдельные
файлы с правами `0600`. Сайт показывает источник значения и приоритет переменных
окружения. Сброс удаляет сохранённое значение; переменные окружения сохраняют
приоритет. Ключи не возвращаются браузеру. После изменения embeddings выполните
`ygg redeploy`; после изменения идентификатора или пространства — `ygg ui --restart`.

Operations предлагает три карточки задач: начальное наполнение (`seed`),
диагностику (`doctor`) и синхронизацию (`sync`). Основной список содержит
14 повседневных команд с описаниями и группами; дополнительные команды
открываются переключателем Advanced. Алиасы, команды запуска серверов,
stdio, токена и самого интерфейса исключены только из селектора Operations.
В терминале они сохранены. Конфигурация редактируется через Settings,
а обновление открывается через значок версии.

| Группа | Назначение | Доступность |
| --- | --- | --- |
| Import & sync | Наполнение из истории, импорт, обработка файлов и синхронизация | Основной список |
| Inspect & search | Статистика, диагностика, модели и поиск; дополнительные проверки качества | Основной список; редкие проверки — Advanced |
| Maintenance | Индексация, запуск, перезапуск и логи; остановка, развёртывание и регистрация | Основной список; изменение установки — Advanced |
| Memory management | Ручное редактирование, связи, экспорт, ревью и удаление памяти | Advanced |
| Setup & integrations | Установка, подбор моделей, хуки и интеграции с агентами | Advanced |
| CLI help | Справка и версия для диагностики команды | Advanced |

Всего при включённом Advanced доступны 44 команды. Такое разделение оставляет
обычные задачи на виду и убирает редкие административные действия из первого
выбора. Карточки задач только выбирают команду: перед запуском можно проверить
аргументы. Для `seed` сначала предлагается `--dry-run`, который показывает план
импорта без записи новых воспоминаний.

Во время операции доступны аргументы, прогресс, вывод, статус, код завершения
и остановка. Команды передаются непосредственно Python без shell.
Пути с пробелами заключайте в кавычки. Команды, меняющие данные или сервисы,
требуют подтверждения в интерфейсе. Одновременно выполняется одна команда;
на время выполнения сохранение конфигурации блокируется.

Для интерактивных команд доступны ответы на приглашения, стрелки, Enter и EOF.
Перед вводом секретов включайте Hide input: они маскируются в выводе. На POSIX
используется PTY; на Windows доступен строковый ввод без полноценной эмуляции
терминала. Остановка завершает только запущенную Workspace команду (на POSIX —
её группу процессов). Она не отменяет уже выполненные изменения.

История операций хранится в памяти процесса: не более 32 запусков и 128 КиБ
вывода на запуск. Обновление страницы сохраняет текущие операции; перезапуск
Workspace очищает историю. Завершённые операции обновляют список проектов.

## Разработка и упаковка

Исходники интерфейса находятся в `web/`:

```sh
cd web
npm ci
npm test
npm run build
```

Сборка помещается в `yggdrasil/workspace_static/` и входит в Python-пакет.
Для обычного запуска установленного пакета Node.js не нужен. После изменения
frontend пересоберите статику перед упаковкой. Шрифты и зависимости
поставляются локально, без CDN.

Python-проверки:

```sh
python3 -m unittest discover -s tests
```

Если движок уже работал до обновления и не знает `/workspace/query`, выполните
`ygg redeploy`. Веб-сервер не перезапускает чужой процесс автоматически.
Ошибки запуска Workspace записываются в `$YGG_HOME/logs/workspace.log`.
Для остановки самого Workspace найдите его процесс по модулю
`yggdrasil.ygg_workspace --serve`; `ygg stop` управляет движком памяти,
а не отдельным процессом Workspace.
